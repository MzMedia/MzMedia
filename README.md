## 📌 平台简介

**MzMedia** 是一款专为**中小企业量身打造的企业级 AI 驱动物联网与视频融合平台**。平台基于成熟的 `ruoyi-vue-pro` 企业级底座深度重构与孵化，深度融合 **物联网（IoT）**、**安防音视频（GB28181 / WebRTC）** 与 **生成式 AI（Spring AI / MCP）** 技术。

针对中小企业在数字化升级中普遍面临的 **“协议碎片化、系统各自为政、数据烟囱林立、商业套件成本高昂”**等核心痛点，MzMedia 提供了从**设备立项、物模型配置、低成本协议接入、多设备联动、实时监控大屏、到智能运维工单闭环**的全生命周期管理能力，实现**设备接入低成本、跨协议集成智能化、业务系统无缝打通**的新一代 AIoT 解决方案。

| :--- | :--- | :--- |

## 🤖 AI 赋能：打通多协议集成与消除协议壁垒

中小企业进行设备联网时，**最头疼的问题就是面对五花八门的非标协议和老旧工业设备**。MzMedia 深度融合 **Spring AI** 与 **大模型智能体（AI Agent）**，通过 AI 解决跨协议集成的“最后一公里”：

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │                      AI 驱动的跨协议接入与调度中枢                    │
 └────────────────────────────────────────────────────────────────────────┘
       ▲                                 ▲                           ▲
 ┌─────┴───────────────┐     ┌───────────┴───────────┐     ┌─────────┴─────────┐
 │ 1. 协议逆向与代码生成 │     │ 2. 跨协议物模型语义对齐 │     │ 3. 跨系统智能体调度 │
 ├─────────────────────┤     ├───────────────────────┤     ├───────────────────┤
 │ 输入非标十六进制报文  │     │ Modbus / MQTT / CoAP  │     │ Spring AI + MCP   │
 │ 或协议规范 PDF 文档   │     │ GB28181 / TCP 私有流  │     │ 自动化排查设备故障 │
 │ 自动生成 Netty 解码器 │     │ 统一转化为 TSL 标准语义│     │ 自然语言下发多端联动│
 └─────────────────────┘     └───────────────────────┘     └───────────────────┘
```

### 1. 私有非标协议智能生成编解码器（Zero-Code Onboarding）
- **痛点**：中小企业常有定制仪器仪表，缺少标准驱动，手写 Netty/Vert.x 编解码插件周期长、调试成本高。
- **AI 赋能**：只需在平台上传设备协议手册（PDF/Markdown）或粘贴抓包十六进制报文，平台内置的 AI 编码助手即可自动推理报文帧头、校验码算法（CRC16/LRC/CheckSum）、长度域和数据段，**一键生成符合 MzMedia 规范的 Java 编解码器代码与单元测试用例**，设备接入从“数周”缩短至“半小时”。

### 2. 跨协议物模型语义归一化（TSL Normalization）
- **消除协议壁垒**：无论底层是 Modbus 寄存器地址（`0x03 40001`）、MQTT JSON 负载（`{"temp": 28.5}`）、CoAP 紧凑二进制，还是 GB28181 XML 状态通知，系统通过 AI 辅助映射，将其统一归纳为物模型**属性（Property）**、**服务（Service）**、**事件（Event）**。
- **上层无感透明调用**：业务层、数字驾驶舱以及移动端无需知晓底层通信细节，只需面向统一的物模型属性读取或下发服务，网关层自动转译为目标协议报文。

### 3. AI 驱动的跨协议即时转译与指令互操作
- **破除协议孤岛**：利用平台内置的智能规则引擎与 AI 语义转译，实现跨协议即时互动。
- **典型范例**：
  - HTTP Webhook 收到第三方环保平台超标警报；
  - AI 智能调度引擎瞬间将其转译为 Modbus TCP 协议指令，下发至 PLC 控制器闭合排污阀门；
  - 同时触发 GB/T 28181 国标协议，向就近的海康球机发送 PTZ 预置位调用指令，自动聚焦排污口并抓拍现场快照。

### 4. AI Agent 与 MCP（Model Context Protocol）运维智能体
- 平台深度适配 Model Context Protocol（MCP），向大模型暴露设备查询、参数调优、时序分析、服务调用等标准 Tools。
- **自然语言运维交互**：工程师只需在后台对话框提问：“*二号机房昨天下午有无温度异常？原因可能是什么？*”，AI Agent 自动调取 TDengine 历史时序曲线、检索告警日志并结合企业知识库（RAG），输出排查结论并生成维保建议。

## 🎯 四大常用 AI 物联网业务场景落地

### 场景一：中小企业物联网项目全周期管理（PMS + IoT）
- **痛点破解**：中小企业承接智能化工程时，常常面临“现场设备装了多少、到了哪些、谁在负责、何时验收”信息混乱的局面。
- **落地链路**：
  1. **立项规划**：在 `PMS` 模块建立物联网交付项目，定义里程碑节点（勘测、布线、通电、入网、终验）；
  2. **物料联动**：项目所需网关与传感器直接联动 `WMS` 仓库预占出库，设备串号一键扫码绑定至项目；
  3. **批量入网**：通过 `IoT` 模块自动分配激活密钥，现场工程人员上电即自动注册到对应项目节点；
  4. **交付看板**：大屏实时展示当前项目设备在线率、信号强度、施工进度，项目结项自动归档为企业固定资产。

### 场景二：低成本设备全生命周期运维与工单闭环（O&M + Flowable + AI）
- **痛点破解**：传统设备维保全凭经验“坏了才修”，现场技术人员排查困难，服务记录易丢失。
- **落地链路**：
  1. **健康体检**：底层 TDengine 实时接收设备上报数据，高频分析振动、电流、温升等健康指标；
  2. **智能预警**：规则引擎触发早期隐患告警，AI 运维助手秒级生成诊断报告（列出可能失效部件与更换方案）；
  3. **工单自动派发**：通过 `Flowable` 流程引擎根据地理位置与岗位自动派发排障工单到维保工程师移动端；
  4. **维保留痕**：工程师通过移动端查看 AI 提供的排查指引，处理完毕上传现场照片与更换备件明细，闭环归档。

### 场景三：多设备跨协议与音视频深度智能联动（IoT + Media + AI）
- **痛点破解**：告警与视频监控割裂，安防监控沦为“事后查录像”，无法实现防患于未然。
- **落地链路**：
  1. **立体感知**：周界红外传感器（Modbus/LoRa）或烟感探测器（MQTT/NB-IoT）感应到异常指标；
  2. **跨系统联动**：规则引擎瞬间唤醒国标视频服务（`yudao-module-media`），指挥就近球机快速旋转至预置位并拉近变焦；
  3. **AI 视觉复核**：截取关键帧交由多模态大模型进行二次识别（烟雾、明火、入侵人员穿戴识别）；
  4. **处置驱动**：确认险情后，系统自动向现场控制器（TCP/UDP）下发喷淋灭火或广播告警指令，同时向管理人员微信群/短信推送带现场截图的告警卡片。

### 场景四：数字大屏驾驶舱与时序透视（GoView + TDengine）
- **痛点破解**：给领导和客户汇报时缺少直观的视觉呈现，自研大屏耗时费力且难以维护。
- **落地链路**：
  1. **拖拽式搭建**：开箱集成 GoView，提供仪表盘、拓扑图、折线图、3D 组态、高德/百度 GIS 地图等数十种物联组件；
  2. **多源数据融合**：大屏同时连接业务数据库（MySQL）与时序数据库（TDengine），秒级展现数万台设备的历史能耗、利用率与告警分布；
  3. **音视频无缝融合**：大屏任意窗口支持直接嵌入 WebRTC/FLV/HLS 低延迟视频画面，实现“看数据”与“看现场”同屏呈现；
  4. **多端自适应**：支持大屏电视墙、PC 浏览器、平板移动端自适应展现，助力中小企业低成本打造高端数字展厅。

| **工业工控协议** | **Modbus TCP / RTU** | PLC、变频器、智能电表、传感器采集模块，支持主动轮询与被动上报。 |
| **低功耗网络** | **CoAP (Californium)** | NB-IoT 窄带物联网、野外水文监测、电池供电微型传感器。 |
| **通用网络协议** | **HTTP / HTTPS REST** | 智能硬件主动推送、三方系统数据推送、微服务轻量交互。 |
| **实时全双工** | **WebSocket** | 网页端与移动端实时指令交互、状态秒级同步。 |
| **原生底层传输** | **TCP / UDP** | 老旧设备私有报文接入，支持定长、分隔符、长度字段及自定义编解码。 |
| **安防国标标准** | **GB/T 28181 (2016/2022)** | 海康、大华、宇视等主流安防监控设备、NVR、IPC，支持视频点播、PTZ、对讲。 |
| **通用流媒体** | **RTSP / RTMP / WebRTC / FLV** | 网络摄像机流媒体转发、低延迟网页播放、移动端推流直播。 |
| **开放视频接口** | **ONVIF** | 局域网内网络摄像机自动发现、属性配置、PTZ 与流地址获取。 |
| **远程终端管理** | **TR-069 / TR-369 (USP)** | 宽带网关、路由器、CPE 等运营商级终端设备的集中参数配置与远程诊断。 |

### 插件化自主扩展架构
MzMedia 采用高度解耦的插件化协议设计：
- **`IotProtocol` 统一接口规范**：标准化定义协议实例的 `start()`、`stop()`、`isRunning()` 完整生命周期；
- **动态装载与热启停**：协议端口、线程池与编解码策略均可通过后台数据库动态调整，无需重启整机服务；
- **上下行 Handler 分离**：上行数据解码（Decode -> 物模型标准化）、下行指令编码（Encode -> 设备通信信道）各自独立，便于单元测试与 AI 辅助生成。

## 🚀 快速开始与部署

### 方式一：Docker 一键快速编排（推荐体验）

平台提供完整的 `docker-compose` 编排文件，一键拉起所需中间件环境：

```bash
# 1. 克隆代码仓库
git clone https://gitee.com/mzmedia/mz-media.git
cd mz-media

# 2. 进入脚本目录启动核心依赖容器 (MySQL, Redis, TDengine, EMQX, MinIO, ZLMediaKit)
cd script/docker
docker-compose up -d

# 3. 检查各容器健康状态
docker ps
```

### 方式二：本地研发环境启动

#### 1. 环境准备
- **JDK**：21 或以上版本；
- **Maven**：3.8+；
- **Node.js**：18+ 及 pnpm。

#### 2. 初始化数据库
- 在 MySQL 中创建名为 `ruoyi-vue-pro` 的数据库（编码 utf8mb4）；
- 执行 `sql/mysql/ruoyi-vue-pro.sql` 初始化基础表与字典；
- 执行 `sql/module/` 下的 `media` 与 `iot` 专属业务脚本。

#### 3. 启动后端工程
- 打开 IDEA，导入根目录 `pom.xml`；
- 修改 `yudao-server/src/main/resources/application-local.yaml` 中的 MySQL、Redis、TDengine 连接信息；
- 找到 `cn.iocoder.yudao.server.YudaoServerApplication`，直接运行 `main` 方法启动。

#### 4. 启动前端项目
```bash
# 进入前端工程目录
cd ui

# 安装依赖
pnpm install

# 启动开发服务器
pnpm run dev
```
打开浏览器访问：`http://localhost:80`（默认管理员账号：`admin`，密码：`admin123`）。
